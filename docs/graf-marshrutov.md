
По набору точек на карте (места из чата / RAG) нужно связать их рёбрами — «по чему можно пройти» — и посчитать путь от одной точки к другой, иногда несколько вариантов маршрута.

Это не навигатор вроде «Яндекса» по всем улицам. Это упрощённая модель: граф только между выбранными точками, с опциональной подмешкой реальных расстояний через OSRM, если сервис настроен.

## Шаг 1. Расстояния «по птице»

Между всеми парами точек сначала считается короткая дуга на сфере (haversine) — сколько метров «напрямик» по кривой Земли.

## Шаг 2. Кого рассматривать кандидатами в рёбра

Собирается пул возможных связей (кандидаты):

- Delaunay (триангуляция) по проекции точек на сферу: типичная для гео вязка в «псевдо-3D». В рёбра идут стороны треугольников, если длина ребра не слишком больше заданного радиуса (по конфигу).
- Плюс k ближайших соседей (kNN) по расстоянию для каждой точки.

В итоге получается густая, но разумно ограниченная сеть возможных скачков между точками — не «каждая с каждой» (так слишком дорого и шумно).

## Шаг 3. Паутинка от важных мест (hub / лучи)

Точкам задан вес важности. Важные «хабы» ведут себя как центр сети: для всех, у кого вес выше порога (в коде `hub_threshold`, сейчас 4.0), насильно добавляются связи к N ближайшим соседям — как лучи от середины сети к краям, даже если эта пара не попала в Delaunay/kNN так агрессивно.

Смысл: не потерять важные достопримечательности как узлы маршрута и улучшить связность туристически значимых мест.

## Шаг 4. Отбор рёбер и степеней узла

Кандидатам назначается численный score (см. конфиг: расстояние, веса, штраф за дальний прыжок). Опционально в оценку подмешивается матрица OSRM (авто- и пешеходные расстояния), если сервис доступен.

Рёбра сортируют по возрастанию score и жадно проходят по списку с ограничением: сколько связей может быть у каждой точки (и база, и бонус от веса).

Итог — разреженный связный (иначе дотягивается в `_ensure_connectivity`) набор рёбер, по сути настоящая сеть для обхода точек.

## Шаг 5. Геометрия маршрута между соседями по ребру

Для выбранных рёбер запрашиваются ломаные по реальным дорогам/тропам (OSRM route), чтобы на карте рисовалось не прямая линия, а путь вдоль дорог, когда OSRM есть.

Матрицу расстояний для графа уточняют длиной по этой геометрии: по рёбрам ломаных посчитанная длина.

## Шаг 6. Поиск путей в сети

Граф переносят в NetworkX: рёбра с весом, равным уже подставленной дистанции. От первой к последней точке (или другое S/T по запросу API) ищут K кратчайших простых путей (алгоритм в духе Йена через `shortest_simple_paths` в NetworkX).

На выходе API: рёбра, варианты маршрутов, GeoJSON для отрисовки.

## В одной фразе

Собрали кандидатов связей (триангуляция + соседи) → добавили лучи от важных точек → отфильтровали по оценкам и связности → дотянули полилинии по OSRM → ищем короткие маршруты в NetworkX.

---

Слово «паутинка» про такой рой рёбер-кандидатов и лучей от «центра» к соседям. В коде функция `_add_hub_spokes` как раз добавляет лучи от хабов (точек с высоким весом).
