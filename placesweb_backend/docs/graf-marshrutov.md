# Как устроен граф маршрутов (простыми словами)

Реализация в сервисе **placesweb_backend**: `app/core/graph_builder.py`, `pathfinding.py`.

## Зачем это нужно

По набору **точек на карте** (места из чата / RAG) нужно **связать** их **рёбрами** — «по чему можно пройти» — и **посчитать путь** от одной точки к другой, иногда **несколько вариантов** маршрута.

Это **не** навигатор «как в Яндексе» по всем улицам: это **упрощённая модель** — граф **между выбранными** точками, с опциональной подмешкой **реальных** расстояний через **OSRM**, если оно настроено.

## Шаг 1. Расстояния «по птице»

Между **всеми** парами точек сначала считается **короткая** дуга на сфере (haversine) — «сколько **метров** **напрямик** **по кривой** Земли».

## Шаг 2. Кого вообще рассматривать кандидатами в рёбра

Собирается **пул возможных** связей — **кандидаты**:

- **Delaunay** (триангуляция) по **проекции** точек на сферу: в «псевдо-3D» вязка, типичных для гео-триангуляции. Рёбра **треугольников**, **если** длина ребра **не** слишком **больше** заданного **радиуса** (по конфигу).
- Плюс **k ближайших соседей** (kNN) по расстоянию для **каждой** точки.

То есть сначала появляется **густая, но** **разумно** **ограниченная** «паутинка» **возможных** **скачков** **между** **точками** — **не** «каждая с каждой» (так слишком **дорого** и **шумно**).

## Шаг 3. «**Паутинка**» **от** **важных** **мест** (hub / лучи)

Точкам **задан** **вес** (важности). **Тяжёлые** (важные) **хабы** ведут **себя** **как** **центр** **сети**:

- у **всех** **чьё** **значение** **веса** **высоко** (в коде — **порог** `hub_threshold`, сейчас 4.0) **насильно** **добавляются** **связи** **к** **N** **ближайшим** **соседям** (лайки **лучи** **от** **середины** **паутинки** к **краям**), даже **если** **эта** **пара** **не** **попала** **в** **Delaunay/kNN** **так** **агрессивно**.

**Интуиция:** **не** **потерять** **важные** **достопримечательности** **как** **узлы** **маршрута** — **улучшить** **связность** **туристически** **значимых** **мест**.

## Шаг 4. Отбор **реальных** **рёбер** и **степеней** **узла**

**Кандидатам** **назначается** **численный** **score** (см. конфиг: расстояние, веса, штраф **за** **дальний** **прыжок**). **Опционально** **в** **оценку** **подмешивается** **матрица** **OSRM** (авто- / **пешие** **расстояния**), **если** **сервис** **доступен**.

**Рёбра** **сортируются** **по** **возрастанию** **score** **и** **жадно** **бегут** **по** **списку** **с** **ограничением** **скольких** **связей** **может** **быть** **у** **каждой** **точки** (и **база**, **и** **бонус** **от** **веса**).

**Итог** — **разреженный** **связный** (иначе **добивается** **в** `_ensure_connectivity`) **набор** **рёбер** — **и** **настоящая** **паутинка** **для** **похода** **по** **точкам**.

## Шаг 5. Геометрия **маршрута** **между** **соседями** **по** **рёбру**

**Для** **выбранных** **рёбер** **запрашиваются** **ломаные** **по** **реальным** **дорогам/тропам** (через **OSRM** **route**), **чтоб** **на** **карте** **рисовалось** **не** **прямой** **линия**, **а** **человеческий** **путь** (когда **OSRM** **есть**).

**Матрица** **расстояний** **для** **графа** **уже** **уточняется** **длины** **по** **этой** **геометрии** **(по** **рёбрам** **ломаных** **посчитанная** **длина**).

## Шаг 6. Поиск **путей** **в** **сети**

**Граф** **переезжает** **в** **NetworkX** **(невзвешенные** **рёбра** **с** **весом** **=** **уже** **подставленной** **дистанцией**). **С** **первой** **на** **последнюю** **точку** **(или** **другое** **S/T** **—** **по** **запросу** API) **ищутся** **K** **кратчайших** **простых** **путей** (алгоритм **Йена**-подобный **через** `shortest_simple_paths` **в** **NetworkX**).

**Итог** API: **рёбра**, **альтернативы** **маршрутов**, **GeoJSON** **для** **отрисовки**.

## Коротко в одной фразе

**Собрали** **кандидатов** **связей** (триангуляция + соседи) → **добавили** **лучи** **от** **важных** **точек** → **отфильтровали** **по** **оценкам** **и** **связности** → **дотянули** **настоящие** **полилинии** **по** **OSRM** → **ищем** **короткие** **маршруты** **по** **NetworkX**.

---

*Термин «паутинка» в разговоре в основном **от** **такого** **роя** **рёбер**-**кандидатов** **и** **лучей** **от** **«центра»** **к** **соседям**; **в** **коде** **функция** ` _add_hub_spokes` **буквально** **докручивает** **лучи** **от** **«хабов»** (точек **с** **высоким** **весом**).*
